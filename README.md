# مشروع التنبؤ بالسكتة الدماغية (Medical-Grade Stroke Prediction Pipeline)

## 📌 1. نوع المشكلة (Problem Type)

* **نوع المهمة:** تصنيف ثنائي (Binary Classification).
* **الهدف الطبي:** بناء نمو\ج تعلم اله طبي دقيق للتنبؤ بما إذا كان المريض معرضاً لخطر الإصابة بالسكتة الدماغية أم لا، مع إعطاء أولوية قصوى لمقياس الاسترجاع (Recall) لتقليل حالات الإنذار الخاطئ السلبي (False Negatives) وضمان عدم تفويت أي مريض مصاب.

---

## 📊 2. نظرة عامة على البيانات (Dataset Overview)

يعتمد النموذج على مجموعة بيانات طبية وديموغرافية تتضمن العوامل الرئيسية المرتبطة بالسكتة الدماغية، ومن أبرزها:

* **المؤشرات الشخصية:** العمر (age)، الجنس (gender)، الحالة الاجتماعية، ونطاق السكن.
* **التاريخ الطبي:** الإصابة بارتفاع ضغط الدم (hypertension)، وأمراض القلب (heart_disease).
* **المؤشرات الحيوية والايضية:** متوسط مستوى السكر في الدم (avg_glucose_level)، ومؤشر كتلة الجسم (bmi).
* **نمط الحياة:** حالة التدخين (smoking_status) ونوع العمل.

---

## ⚙️ 3. الخوارزميات والتقنيات المستخدمة (Algorithms & Libraries)

* **خوارزمية التعلم الآلي:** Logistic Regression (تم اختيارها بعد المقارنة لتميزها في الاستقرار والأداء الطبي مع ضبط الأوزان class_weight='balanced').
* **بنية العمل:** استخدام Pipeline و ColumnTransformer من مكتبة Scikit-Learn لضمان معالجة البيانات بسلاسة ومنع تسرب البيانات (Data Leakage).
* **التحسين والتنظيم:** استخدام GridSearchCV للبحث عن أفضل المعاملات الفائقة (Hyperparameters).

---

## 🛠️ 4. خطوات العمل ومراحل البناء بالترتيب (Step-by-Step Pipeline)

1. **المعالجة المسبقة وتنظيف البيانات (Preprocessing):** معالجة القيم المفقودة (مثل قيم bmi المفقودة) وترميز المتغيرات النصية وتوحيد مقياس البيانات الرقمية.

2. **هندسة الخصائص المتقدمة (Feature Engineering):** إضافة خصائص جديدة مبتكرة باستخدام FunctionTransformer مثل نسبة السكر إلى مؤشر كتلة الجسم (glucose_to_bmi_ratio) والتفاعل المشترك بين العمر والسكر (age_glucose_interaction).

3. **ضبط المعاملات الفائقة والتدريب (Hyperparameter Tuning):** دمج خطوات المعالجة والنموذج في Pipeline متكامل واستخدام GridSearchCV مع التحقق التقاطعي (5-Fold Cross-Validation).

4. **ضبط عتبة القرار (Threshold Tuning) لأجل الأمان الطبي:** اعتماد عتبة قرار مخفضة (Threshold = 0.3) لضمان التقاط أكبر عدد ممكن من الإصابات الحقيقية ورفع نسبة Recall.

5. **حفظ النموذج (Model Persistence):** حفظ الـ Pipeline المدرب بالكامل في ملف بصيغة .pkl باستخدام مكتبة joblib تحت اسم best_stroke_tuned_pipeline.pkl.

6. **الاختبار والتنفيذ النهائي (Inference):** كتابة كود مخصص لتحميل النموذج المحفوظ واستخدامه للتنبؤ باحتماليات الإصابة لبيانات المرضى الجدد بكفاءة عالية.
